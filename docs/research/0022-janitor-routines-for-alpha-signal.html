Hiring a cleaning crew for Alpha Signal

About a 6-minute read. No jargon that isn't explained on the spot. Companion to The Night Janitors.

The team that builds Claude Code lets Claude tidy their own software every night, and a human signs off each change. This page says what the same idea looks like for our system, who does what, and the six yes/no calls that only you can make.

The idea in one picture

Think of Alpha Signal as a house. Every day new stuff comes in: prices, filings, code, tables. Nobody cleans, because cleaning is boring and there is always something more urgent. So we hire a crew. The crew cannot throw anything away. It can only put things in a box labelled "throw this?" and leave the box at your door. You look inside once a week and say yes or no.

The crew finds. You decide. A session of Claude Code does the actual removal, on a side branch, after you say yes.

The one rule

Nothing is deleted, rewired or overwritten by the crew on its own. Ever. That rule is what makes it safe to let them run every day.

Meet the three crew members

In our system a "crew member" is a seat: a named job in the agent org we already run (the same org that produces the CIO review and the data-quality audit each week). Each seat gets a short written job description and a time slot. Here are the three we would add or extend.

Build first

The Data Bug Fixer

Looks for: numbers that are wrong while looking right. A share count 22 times too small. A company scored on figures from before it split in two. A quarter's sales that include a one-off windfall.

Why first: these move the picks. Garbage in, garbage out. We already have a weekly auditor that finds such things; this adds the eleven error types the research agents caught that it still misses, and turns each finding into a ready-to-approve fix.

Build second

The Code Janitor

Looks for: code nobody uses any more (110 tools, old study scripts, a temporary job that was due for removal last week), tests that cannot fail, settings stuck in one position for months, and two helpers that do the same thing.

Why it matters: clutter doesn't break anything. It wastes every future session's time reading it.

Build last

The Data Simplifier

Looks for: tables nothing reads, two tables holding the same fact and disagreeing, and new tables created when an existing one would do. We have 188 tables; the redesign we approved maps them to 24.

Why last: the big move is already designed. It is waiting on three calls from you (below), not on a robot.

The clever bit: flag first, remove later

Removing things is scary. "Nobody uses this" is easy to say and hard to prove. So the crew never removes on a hunch. It puts a sticker on the thing and waits two weeks.

For code, the sticker is a one-line note that writes "I ran!" to our event log whenever that code is used. Two weeks of silence is proof. For data, the sticker is a flag on the suspect number, plus a record of which stock picks would move if it were corrected. Only then does the correction go in. Yesterday's picks never change silently.

A guess becomes a measurement. This is the single idea from the Anthropic story most worth copying.

How a week would go

Your total time: about ten minutes on Monday, and a half-hour session roughly twice a month once the first backlog is cleared.

Three terms, since they appear above. A memo is the crew's weekly note: what it found, what it suggests, with the evidence. A work order is a numbered to-do you create by pressing one button on the memo; it is the only way a change gets made. Merge means accepting a finished change into the real system, which you do by hand.

Jargon buster

Seat
A named job in our agent org, with a written job description and a time slot. The CIO review and the data-quality audit are seats.
Probe
A small program that scans for one kind of problem and reports counts with evidence. The seat judges what the probe found; the probe never judges.
Memo
The seat's weekly note, stored in the system and shown on the Boardroom page.
Work order
A numbered, approved to-do. The only route by which anything gets changed.
Branch
A side copy of the code where a change is made and tested before it touches the real thing.
Merge
Accepting a finished branch into the real system. You do this by hand.
Sticker
Our word on this page for the "log first, delete later" trick: a flag on a suspect, then two weeks of waiting for evidence.
Picks
The daily ranked stock list the whole system exists to produce. "Touches the picks" is the highest-priority label a finding can get.

Tail piece

Anthropic's lesson wasn't that the robot is a great cleaner. It was that cleaning finally had a date on the calendar and a human with a short list to say yes or no to. The crew does the boring part; you keep the only part that needs judgment.
